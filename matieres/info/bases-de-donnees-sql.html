🗄️ Bases de données & SQL

Modèle relationnel, contraintes d&#x27;intégrité, LDD, LMD, requêtes SELECT, jointures, agrégations et sous-requêtes.

Le modèle relationnel

Une base de données relationnelle stocke des données structurées dans des tables (relations) reliées entre elles, gérées par un SGBDR (comme MySQL).

Table (Relation)
Ensemble d'occurrences d'une même entité, organisée en colonnes (attributs/champs) et en lignes (enregistrements/tuples).
Clé primaire (PRIMARY KEY)
Attribut (ou combinaison d'attributs) qui identifie de manière unique chaque ligne. Jamais nulle ni dupliquée.
Clé étrangère (FOREIGN KEY)
Attribut d'une table qui fait référence à la clé primaire d'une autre table (table mère) pour assurer l'intégrité référentielle.

Règles de passage vers le modèle relationnel

1 → N (père / fils)

La clé primaire de la table côté 1 migre comme clé étrangère dans la table côté N.

N → M (plusieurs à plusieurs)

Création d'une table associative contenant les clés primaires des deux tables (clé primaire composée) + les attributs propres à l'association.

Contraintes d'intégrité essentielles

Contrainte SQLRôle et signification
PRIMARY KEYIdentifie de façon unique chaque ligne (implique NOT NULL et UNIQUE).
FOREIGN KEY ... REFERENCESAssure qu'une valeur existe bien dans la table mère (intégrité référentielle).
NOT NULLInterdit les valeurs vides (NULL) dans la colonne (saisie obligatoire).
UNIQUEGarantit que toutes les valeurs de la colonne sont distinctes (ex. : email, CIN).
CHECK (condition)Impose une contrainte de domaine sur les valeurs (ex. : CHECK (prix > 0)).
DEFAULT valeurAttribue une valeur par défaut lorsqu'aucune valeur n'est précisée à l'insertion.
AUTO_INCREMENTIncrémente automatiquement une clé primaire entière à chaque nouvelle insertion.

Langage de Définition de Données (LDD / DDL)

Le LDD permet de créer, modifier et supprimer la structure de la base et des tables.

CREATE DATABASE bd_commerce;
USE bd_commerce;

CREATE TABLE Client (
    idCli INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(50) NOT NULL,
    email VARCHAR(80) UNIQUE,
    ville VARCHAR(30) DEFAULT 'Tunis',
    age INT CHECK (age >= 18)
);

CREATE TABLE Commande (
    numCmd INT PRIMARY KEY,
    dateCmd DATE NOT NULL,
    montant DECIMAL(8,2) CHECK (montant > 0),
    idCli INT NOT NULL,
    FOREIGN KEY (idCli) REFERENCES Client(idCli)
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- Modifications de structure (ALTER TABLE) et suppression (DROP)
ALTER TABLE Client ADD tel VARCHAR(8);
ALTER TABLE Client MODIFY nom VARCHAR(60) NOT NULL;
ALTER TABLE Client DROP COLUMN tel;
DROP TABLE Commande;

Langage de Manipulation de Données (LMD / DML)

Le LMD permet d'ajouter, de modifier ou de supprimer des enregistrements dans les tables.

-- Insérer un enregistrement
INSERT INTO Client (nom, email, age)
VALUES ('Sami', 'sami@mail.tn', 22);

-- Mettre à jour des lignes (ne jamais oublier WHERE !)
UPDATE Client
SET ville = 'Sousse', age = age + 1
WHERE idCli = 1;

-- Supprimer des lignes
DELETE FROM Commande
WHERE dateCmd < '2025-01-01';

Interrogation des données (LID : SELECT)

L'ordre logique d'écriture d'une requête SELECT complète est toujours :

SELECT [DISTINCT] colonnes_ou_fonctions
FROM table1, table2
WHERE condition_sur_les_lignes_et_jointures
GROUP BY colonne_de_regroupement
HAVING condition_sur_les_groupes
ORDER BY colonne [ASC | DESC];

Opérateurs de filtrage (WHERE)

Opérateur / ClauseUtilisation et exemple
Comparaison & Logique=, <> (ou !=), <, <=, >, >=, AND, OR, NOT.
BETWEEN a AND bValeurs comprises entre a et b inclus. Ex. : age BETWEEN 18 AND 25.
IN (v1, v2, ...)Appartenance à une liste. Ex. : ville IN ('Tunis', 'Sfax', 'Nabeul').
LIKE 'motif'% remplace 0 ou plusieurs caractères ; _ remplace exactement 1 caractère.
Ex. : nom LIKE 'A%' (commence par A), nom LIKE '_a%' (2e lettre est a).
IS NULL / IS NOT NULLTeste si une colonne est vide ou renseignée (ne jamais écrire = NULL).

Jointures, agrégations et sous-requêtes

  • Fonctions d'agrégation : COUNT(*) (nombre de lignes), COUNT(DISTINCT col), SUM(col), AVG(col), MIN(col), MAX(col).
  • Dates et chaînes : YEAR(d), MONTH(d), DAY(d), CURDATE(), UPPER(ch), LENGTH(ch).
-- 1. Jointure entre deux tables (clients et leurs commandes)
SELECT c.nom, cmd.numCmd, cmd.montant
FROM Client c, Commande cmd
WHERE c.idCli = cmd.idCli
ORDER BY cmd.montant DESC;

-- 2. Regroupement et filtrage de groupes (clients ayant au moins 2 commandes)
SELECT idCli, COUNT(*) AS nbCmd, SUM(montant) AS total
FROM Commande
WHERE YEAR(dateCmd) = 2026
GROUP BY idCli
HAVING COUNT(*) >= 2;

-- 3. Sous-requête (commandes supérieures à la moyenne générale)
SELECT numCmd, montant
FROM Commande
WHERE montant > (SELECT AVG(montant) FROM Commande);

Astuces Bac (SQL)

3 règles d'or pour ne perdre aucun point
  1. WHERE vs HAVING : utilise toujours WHERE pour filtrer les lignes avant regroupement, et HAVING pour filtrer sur une fonction d'agrégation (COUNT, SUM, AVG) après GROUP BY.
  2. Dans une jointure sur k tables, il faut au minimum k - 1 conditions de jointure (clé primaire = clé étrangère) pour éviter le produit cartésien.
  3. En SQL, entoure toujours les chaînes de caractères et les dates (format 'AAAA-MM-JJ') par des guillemets simples.
